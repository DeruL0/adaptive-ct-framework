# 代码框架

从多视角平行束投影重建物体的三维衰减系数场，存成不超过字节预算（主线 8 MiB）的文件。只用投影数据：
不用传统重建结果做初值；GT 体只在训练结束后用于评测和离线诊断。

## 表示
- **八叉树**：物体所在立方体先均匀分成 48×48×48 个格子，任一格子可再一分为八（每条边对半切），
  最多到第 4 层（相当于 768³）。不再切分的格子叫叶子。u 表示叶内坐标（每个方向 0 到 1）。
- **三种叶子**（同一棵树可以混合）：
  - 常数叶：1 个值；
  - 三线性叶：8 个角值，叶内任一点 = 8 个角值按位置的加权平均（叶内连续变化）；
  - 阶跃叶：2 个值 c₀、c₁ 和几何（方向 n、位置 d、宽度 w），叶内值 = (1 − H)·c₀ + H·c₁，
    H = sigmoid((n·(u − ½) − d)/w) 是沿 n 方向、在 d 处、宽度为 w 的光滑阶跃（w = 0 为硬阶跃）。
  三种叶子的值都是存储值的非负加权平均，所以只要存储值 ≥ 0，整个场处处 ≥ 0。
- **切分**保持函数不变：常数子叶照抄父值；三线性子叶取父函数在子叶角上的值；
  阶跃子叶 n 不变，d′ = 2d − n·(o − ½)，w′ = 2w（o 为子叶在父叶中的位置）。
  某个子叶里阶跃较小一侧不到其体积 2% 时，这个子叶改为常数叶（取平均值），
  否则小的一侧对应的值几乎不影响任何射线，求解时会失去约束、数值发散。
- **存储格式**（codec/artifact.py，预算按它计，codec/budget.py）：按层顺序排列（先根网格按光栅顺序，
  再逐层列出每个分叉结点的 8 个子格），每个根格子 1 位（叶子或继续切分）、每个分叉结点一个 8 位掩码
  （哪些子格继续切分）、每个叶子 2 位类型，不存任何指针和坐标，解码时由顺序还原。值用半精度；
  阶跃叶的几何打包成 32 位：方向用八面体编码（把单位球面摊平到正方形上）2×10 位，d 8 位，
  w 按对数刻度 4 位（0 表示硬阶跃）。常数叶 2.25 字节，三线性叶 16.25 字节，阶跃叶 8.25 字节，
  每次切分多 1 字节加 7 个子叶。
- **计算格式**（representation/octree.py，GPU 上）：叶子按类型排成"三线性 | 阶跃 | 常数"，同类型内按
  Z 序曲线（三个坐标的二进制位交错）排列，空间上相邻的叶子在内存里也相邻。叶子的类型和值的位置都由
  序号直接算出：三线性叶 i 的 8 个值在 8i 处（32 字节对齐，两次 128 位读取）。阶跃几何只给阶跃叶存，
  每叶一条 32 字节记录。树 = 根网格一个 32 位数组 + 每个分叉结点一行 8 个 32 位子项（非负为叶子序号，
  负数为分叉结点序号）。值直接是物理衰减系数。
- **投影**：每个探测器像素对应一条直线，预测值是衰减系数沿直线的精确积分（按叶子边界分段计算，CUDA）。
  三线性叶沿线段是三次多项式，两点高斯求积精确；阶跃叶沿线段 s = n·(u − ½) − d 是线性的，
  ∫H = L·(softplus(s₁/w) − softplus(s₀/w))/((s₁ − s₀)/w) 有闭式解。
  几何固定时场对存储值是线性的：预测投影 = A·c，c 是全部存储值排成的向量，A 的元素都 ≥ 0。

## 流水线
```
48³ 根网格（三线性叶），所有值 = 训练投影平均值的一半
重复（每一轮）：
  0. 阶跃几何（有阶跃叶时，值固定为上一轮的解）：一步阻尼高斯-牛顿     (training/geometry.py)
       对每个阶跃叶，按射线累加几何（方向、位置、宽度）的导数 D = (c₁ − c₀)·∂I/∂几何：
       梯度 Σ r·D 和 5×5 矩阵 Σ D·Dᵀ（经过多个阶跃叶的射线，叶间耦合忽略），解 (G + 0.1·diag G)·δ = −g，
       每部分限幅；方向归一化（d、w 同比缩放，函数不变），w ≥ 四分之一探测器像素，平面留在叶内，
       两侧都 ≥ 2% 体积，否则该叶不动；整步使完整目标（投影误差 + β·R）下降才接受，否则步长减半，最多 3 次
  1. 求解：树和叶子类型固定，求  min_{c≥0} ½‖A·c − y‖² + β·R(c)          (training/solve.py, regularizer.py)
       R(c)：保边正则，对所有相邻叶子共享面上的采样点（从较细一侧取 2×2 个点），
             惩罚两侧取值差 t：|t| ≤ δ 时 t²/2（压平叶子间的小台阶），否则 δ(|t| − δ/2)（真实边缘只线性计价）；
             β = 2300、δ = 0.02，在检验视角上选出（合并像素时 β 按像素倍数平方缩小）
       误差 r = A·c − y；梯度 g = Aᵀ·r + β·∇R（把误差反投影回每个系数）
       每个系数的步长分母 d = Aᵀ·A·1 + β·（R 的曲率上界）（保证每步不会让目标变大）
       更新 c ← max(0, c − g/d)（小于 0 的置 0，即满足非负约束）
       加速：先把 240 个视角按角度交错分成 24 组、每组更新一次；之后用全部数据更新，
             并在"上一步移动的方向"上额外外推一段（外推点截断到 ≥ 0），方向变差就取消外推
       停止：最优性残差 |c − max(0, c − g(c)/d)| / |c| ≤ 容差（每轮 1e-3，最后一轮 1e-4），在返回的系数 c 上检查：
             外推点上的步长变小时，在新的 c 上多取一次梯度来判断，不通过就从 c 继续（动量重置）
       未收敛时继续解同一棵树（复用 d、动量和正则采样点，不再热身），直到收敛；不改结构。
             整个运行有时间上限（training.max_seconds）：到时保存模型，状态记为 time_limit_not_converged，
             不能称为完成。每轮分别报告：值是否收敛（values_converged）、续解次数、几何更新是否被接受
       粗树用粗数据：最细叶子在探测器上还跨 ≥ 2.5 个合并像素时，把 2×2 或 4×4 个像素取平均当一条射线求解
  2. 决策：每个叶子比较 5 个选项                                         (refinement/decision.py)
       保持 / 换成常数 / 换成三线性 / 换成阶跃 / 切分成 8 个同类子叶
       阶跃的候选几何取自当前重建：n = 叶内（含四分之一叶宽的邻域）灰度梯度二阶矩的主方向，
             d = 沿 n 按梯度大小加权的中心（限制在叶子范围的 80% 以内），w = 半个探测器像素；
             较小一侧不到叶子体积 2% 的候选不允许
       射线：全部 240 个训练视角的全部像素（配置 decision_views），按角度相邻的视角交替分成两半
       局部重新拟合：其余叶子固定（相同背景），对每个选项做最小二乘，并满足与求解相同的约束：
             换类型的值 ≥ 0；切分时每个子叶加一个常数修正，修正 ≥ −（该子叶当前的最小值）
       收益：在一半视角上拟合、在另一半上计算，再反过来，两次相加（多出来的参数只有在没参与拟合的视角上
             也更准时才有收益）。
             换类型：收益 = J(自己类型，值重新拟合) − J(新类型，重新拟合)。换类型整体替换叶内函数，所以基线是旧类型的
                   重新拟合，"把值继续优化"的收益不算给换类型；阶跃叶的基线用它当前的几何，候选用新估计的几何。
             切分：收益 = J(当前函数) − J(当前函数 + 每个子叶一个常数修正)。修正加在当前函数上，这个函数族里没有
                   父叶的重新拟合，所以不扣重拟合基线（实测：切分也扣基线时 8 MiB 体积 PSNR 从 37.38 降到 35.57 dB，
                   深层切分被压低；严格的做法是父叶值和子叶修正联合拟合，需要父叶基函数与子叶长度的交叉项）。
             小于精度的收益记为 0（残差能量的 1e-6 加 b² 的 1e-7：内核权重是 float32）
       目标值与求解相同：每一半为 Σ(预测 − 数据)² + β·R（整体目标 ½‖Ac − y‖² + βR 乘 2 后两半平分）。
             R 在该叶附近换成一个二次函数：每个共享面采样点权重 = 面积 × min(1, δ / 当前两侧差)，
             在当前值处与 R 相等、其余处都不低于 R，所以正则部分的收益不会被高估；
             切分时 8 个子叶之间新出现的内部面也计入（当前差为 0）
       统计量在 CUDA 遍历中累加到每个叶子（每个视角用 float32 累加，视角之间在 double 里相加：
             收益是比自身大得多的量的差，float32 跨视角求和会把它丢掉；拟合和收益按叶子分块在 double 里算）
       限制：三线性叶和阶跃叶不降级成常数叶；上一轮刚换过类型的叶子这一轮只能保持或切分；
             子叶在探测器上必须至少跨 1 个像素
  3. 选择：每个叶子取 "收益 − λ × 多用的字节" 最大且为正的选项；λ ≥ 0 取使这一轮的净增字节
       不超过剩余预算 70% 的最小值（省字节的选项在损失小于 λ × 省下字节时也会被采用）；选中的全部执行
  4. 执行：换类型时，用新类型中与该叶子当前函数最接近的函数初始化（叶内 4³ 个采样点上的最小二乘，值 ≥ 0），
           使模型保持在已求解状态附近；切分保持函数不变；下一轮求解从这里继续
直到：没有净收益为正的选项 / 剩余预算不到 1% / 达到最大轮数 → 最后一轮全分辨率严格求解
导出：存储值和阶跃几何四舍五入到半精度（不再重新拟合；若有值超出半精度范围直接报错），评测，写入紧凑文件
```

## 视角划分
- 训练 240 个视角：求解和决策只用这些。
- 检验 16 个视角：每轮报告投影误差，不参与任何决策。
- 测试 4 个视角：只在最后评测。

## 运行
```powershell
.venv\Scripts\python.exe -m adaptive_ct.training --config configs\stage7\p1.yaml
scripts\test.ps1
```
环境：项目内 `.venv`（Python 3.10，torch 2.11.0+cu130，匹配本机 CUDA 13.0，可重编原生扩展）。
每轮报告：阶跃几何更新（接受的步长、目标前后、用时）、求解遍数、是否收敛、合并像素倍数、检验视角投影 PSNR、字节、叶子类型数、GPU 显存峰值；
每次决策：字节价格 λ、各选项收益为正的叶子数、执行的动作数、这批动作的检验收益、决策各部分用时
（候选几何、正则统计、射线统计、拟合、选择、执行）、阶跃切分里转成常数的子叶数及函数变化。
每次运行保存 states/pre_final_solve.pt 和 states/pre_decision_last.pt；`scripts/audit/benchmark_pipeline.py <运行>` 从这两个状态测
单遍各部分、最后求解（含固定分母的参考残差）和一次决策的耗时，写入 output/_bench/；
`scripts/audit/solver_compare.py <运行>` 从 pre_final_solve.pt 出发在固定树上比较求解器（见下文“求解器对比”）。

## 为什么这么费（8 MiB，实测）
**一遍数据的规模**：240 个训练视角 × 1024² 像素 = 2.5 亿条射线。8 MiB 的树上每条射线平均穿过 90 个叶子（中位 83，最多 261），
段数按类型是阶跃叶 86%、三线性 11%、常数 3%，所以一遍有 228 亿次叶内积分。单遍耗时（RTX 5070 Ti 笔记本，12 GB）：
正投影 0.84 秒（每视角 3.5 毫秒，约 270 亿段/秒，已经接近硬件能给的），反投影内核每视角 5.4 毫秒（正投影的 1.5 倍），
含射线准备、损失、正则的一遍完整梯度约 2.9 秒。

**一次运行花在哪里**（提交 94a53a6，循环 660 秒，另有评测和导出约 60 秒）：

| 部分 | 秒 | 占比 | 为什么 |
|---|---|---|---|
| 最后的严格求解 | 266 | 40% | 65 遍；对角步长的一阶法，边缘等高频成分曲率小、收敛慢（见“求解器对比”） |
| 决策（7 次） | 206 | 31% | 每个（叶子，射线段）要累加 102 个统计量（5 个选项的法方程），每段 1.2 纳秒，是正投影的 14–30 倍；射线统计 141、拟合 48 |
| 每轮解值（8 轮） | 151 | 23% | 每轮约 5 遍，最后几轮是全分辨率 |
| 阶跃几何更新 | 35 | 5% | 每轮一步，统计一遍加一次完整目标检查 |

**根本原因有四个**：
1. **遍数多，不是单遍慢。** 单遍已接近硬件上限，要省只能少走遍数；整个运行约 230 遍整数据的等价量。
2. **一阶对角步长法收敛慢。** AᵀA 对高频成分的曲率很小，对角预条件解决不了；最后 50 遍还在涨 0.27 dB。
   更好的求解器能一次省掉这一项（见下一节：同一参考残差下快约 7 倍）。
3. **决策的统计量重，且 240 个视角不能少。** 视角数 16 → 64 → 240，第 0 层边缘叶能看出切分收益的比例是 17% → 50% → 97%。
4. **轮数多。** 每轮 = 几何更新 + 求解 + 决策，预算按剩余的 70% 逐轮填满，共 8 轮。

**已经做过的加速**（8 MiB 全程 18.4 → 11.9 分钟，结果不变；之后反投影再省一部分，见下）：决策和几何统计的同叶线程分列求和、射线按列排列
（一个线程束的 32 条射线在旋转平面内同路，几乎总落在同一叶子上）、几何更新从上次接受的步长开始试、分组阶段正则梯度每遍只算一次、
反投影内核同样分列求和（每视角完整梯度遍 15.1 → 10.1 毫秒；同状态最后求解 260 → 187 秒；完整运行尚未补测）。
实测后放弃的：每视角新建梯度数组（0.03 毫秒）、解析计算 A·1（每次求解只影响一遍）、按类型或分组大小选择累加方式、改线程块大小
（都更慢）。显存方面：保边正则每个采样点 196 → 24 字节、类型转换分块，使 16 MiB 的峰值从 16.6 GB（溢出到系统内存）降到 8.1 GB。

## 求解器对比（固定树，从 pre_final_solve.pt 出发，`scripts/audit/solver_compare.py`，尚未接入主线）
同一个目标 J(c) = ½‖Ac − y‖² + βR(c)、同一个投影器、正则和非负约束。统一用固定分母的参考残差
ρ_ref(c) = |c − max(0, c − ∇J(c)/D_ref)| / |c|（D_ref = 起点处的 D_L + D_R）在返回的值上判断，耗时只计算法本身（测量用的一遍梯度不计）。
对比的是松弛 OS-LALM（Nien & Fessler 2016，arXiv:1512.04564 的算法 1，W = I，D_L = diag(AᵀA·1)，D_R = β·正则曲率上界，α = 1.999）：

| 方法 | 到 ρ_ref ≤ 1e-4 | 目标值 |
|---|---|---|
| 基线（现行求解器） | 62 遍，182 秒 | 241.516（65 遍） |
| **松弛 OS-LALM，12 个子集，ρ 按子迭代递减，正则梯度每子迭代重算（论文设置）** | **6 轮，26.9 秒** | 6 轮 236.99，30 轮 **235.98**（残差 5.8e-5） |
| 12 个子集，正则梯度每轮只算一次 | 发散 | 7169（残差 1.6e-3） |

- 论文设置下同一参考残差快约 7 倍，而且目标值比基线“收敛”时低 2.3%：基线停下的位置离最小值还远，ρ_ref 这个判据偏松
  （对角分母下的相对步长小，不等于离最优近）。判据本身需要补一个更强的量（例如目标值随遍数的下降）。
- 子集数要小：论文用 10–12，24 个会出现纹波；正则梯度必须每个子迭代都重算，这一项约占一轮的一半时间（12 次 × 0.2 秒）。
- 一轮 12 个子集约 4.5 秒（数据 2.9 秒 + 正则梯度），所以收益来自遍数从 65 降到约 6。
- 接入主线前还要：用体积 PSNR 验证（门槛：体积 PSNR 下降 ≤ 0.02 dB，表面带误差增加 ≤ 0.5%，最后求解至少快 25%）；
  选子集数只用目标值和 ρ_ref，不用 GT；再决定是否也用于每轮解值；接入时按规矩删除旧求解器。

## 已知缺口
- 时间大头是最后的严格求解（约 266 秒、65 遍）和决策（约 30 秒/轮）；前者有松弛 OS-LALM 这条路（见“求解器对比”），后者的统计量可以精简。
- 参考残差 ρ_ref 的判据偏松（基线在它 ≤ 1e-4 时目标值仍比松弛 OS-LALM 高 2.3%），“值收敛”的含义要和它一起重新界定。
- 字节有价格以后，三线性叶换成阶跃叶（省 4 字节）仍被大量采用，平坦区域出现块状。
- DICOM 视野圆外（GT 为零的空气）仍占 13–24% 的字节。注意这不是扫描圆：旋转轴是模型第 2 轴，扫描圆在第 0、1 轴平面内，那里的圆外有物体（GT 均值 0.035），不能置零；DICOM 视野是参考体的性质，只用投影时不能拿来当约束。
- 保边正则的强度只在一棵树上选过（e9f0f68 起决策也计入正则）。
- 阶跃几何每轮只做一步高斯-牛顿，且梯度不含保边正则对几何的导数（接受与否按含正则的完整目标判断）。
- 切分收益按"当前函数 + 每个子叶一个常数修正"估计，不含父叶值的重新拟合（联合拟合需要交叉项，未做）。
- 阶跃切分里，较小一侧不到 2% 的子叶转成常数是有损的：每轮约 4–5 成的阶跃子叶被转换，函数最大变化 0.12–0.5，均方根 0.001–0.004。

只保留当前方法：旧的训练方式、旧的压缩编码、采样积分、高阶多项式叶、随机射线打分等都已从代码中删除，
历史版本只在 git 记录里（标签 `legacy-adam-pipeline` 和此前的提交）。
