# 代码框架

从多视角平行束投影重建物体的三维衰减系数场，存成不超过字节预算（主线 8 MiB）的文件。只用投影数据：
不用传统重建结果做初值；GT 体只在训练结束后用于评测和离线诊断。

## 表示
- **八叉树**：物体所在立方体先均匀分成 48×48×48 个格子，任一格子可再一分为八（每条边对半切），
  最多到第 4 层（相当于 768³）。不再切分的格子叫叶子。u 表示叶内坐标（每个方向 0 到 1）。
- **三种叶子**（同一棵树可以混合）：
  - 常数叶：1 个值；
  - 三线性叶：8 个角值，叶内任一点 = 8 个角值按位置的加权平均（叶内连续变化）；
  - 阶跃叶：2 个值 c₀、c₁ 和几何（方向 n、位置 d、宽度 w），叶内值 = (1 − H)·c₀ + H·c₁，
    H = sigmoid((n·(u − ½) − d)/w) 是沿 n 方向、在 d 处、宽度为 w 的光滑阶跃（w = 0 为硬阶跃）。
  三种叶子的值都是存储值的非负加权平均，所以只要存储值 ≥ 0，整个场处处 ≥ 0。
- **切分**保持函数不变：常数子叶照抄父值；三线性子叶取父函数在子叶角上的值；
  阶跃子叶 n 不变，d′ = 2d − n·(o − ½)，w′ = 2w（o 为子叶在父叶中的位置）。
  某个子叶里阶跃较小一侧不到其体积 2% 时，这个子叶改为常数叶（取平均值），
  否则小的一侧对应的值几乎不影响任何射线，求解时会失去约束、数值发散。
- **存储**：直接存每个叶子的物理值（半精度；阶跃叶另存方向的两个角度、d、w）+ 每叶 3 字节类型标记
  + 每次切分 64 字节树结构；常数叶 5 字节，三线性叶 19 字节，阶跃叶 15 字节。预算按实际存储的字节计。
- **投影**：每个探测器像素对应一条直线，预测值是衰减系数沿直线的精确积分（按叶子边界分段计算，CUDA）。
  三线性叶沿线段是三次多项式，两点高斯求积精确；阶跃叶沿线段 s = n·(u − ½) − d 是线性的，
  ∫H = L·(softplus(s₁/w) − softplus(s₀/w))/((s₁ − s₀)/w) 有闭式解。
  几何固定时场对存储值是线性的：预测投影 = A·c，c 是全部存储值排成的向量，A 的元素都 ≥ 0。

## 流水线
```
48³ 根网格（三线性叶），所有值 = 训练投影平均值的一半
重复（每一轮）：
  1. 求解：树和叶子类型固定，求  min_{c≥0} ½‖A·c − y‖²                     (training/solve.py)
       误差 r = A·c − y；梯度 g = Aᵀ·r（把误差反投影回每个系数）
       每个系数的步长分母 d = Aᵀ·A·1（保证每步不会让目标变大）
       更新 c ← max(0, c − g/d)（小于 0 的置 0，即满足非负约束）
       加速：先把 240 个视角按角度交错分成 24 组、每组更新一次；之后用全部数据更新，
             并在"上一步移动的方向"上额外外推一段（外推点截断到 ≥ 0），方向变差就取消外推
       停止：最优性残差（在可行点上做一次上述更新，系数的相对变化）≤ 容差（每轮 1e-3，最后一轮 1e-4）；
             到遍数上限仍未达到则记为"未收敛"
       粗树用粗数据：最细叶子在探测器上还跨 ≥ 2.5 个合并像素时，把 2×2 或 4×4 个像素取平均当一条射线求解
  2. 决策：每个叶子比较 5 个选项                                         (refinement/decision.py)
       保持 / 换成常数 / 换成三线性 / 换成阶跃 / 切分成 8 个同类子叶
       阶跃的候选几何取自当前重建：n = 叶内（含四分之一叶宽的邻域）灰度梯度二阶矩的主方向，
             d = 沿 n 按梯度大小加权的中心（限制在叶子范围的 80% 以内），w = 半个探测器像素；
             较小一侧不到叶子体积 2% 的候选不允许
       射线：全部 240 个训练视角的全部像素（配置 decision_views），按角度相邻的视角交替分成两半
       局部重新拟合：其余叶子固定（相同背景），对每个选项做最小二乘，并满足与求解相同的约束：
             换类型的值 ≥ 0；切分时每个子叶加一个常数修正，修正 ≥ −（该子叶当前的最小值）
       收益 = 目标值(保持) − 目标值(选项)，在一半视角上拟合、在另一半上计算，再反过来，两次相加
             （多出来的参数只有在没参与拟合的视角上也更准时才有收益；量级在残差能量 1e-6 以内的收益记为 0）
       统计量在 CUDA 遍历中直接累加到每个叶子（同一线程束内先合并再原子累加）
       限制：三线性叶和阶跃叶不降级成常数叶；上一轮刚换过类型的叶子这一轮只能保持或切分；
             子叶在探测器上必须至少跨 1 个像素
  3. 选择：每个叶子取 "收益 − λ × 多用的字节" 最大且为正的选项；λ ≥ 0 取使这一轮的净增字节
       不超过剩余预算 70% 的最小值（省字节的选项在损失小于 λ × 省下字节时也会被采用）；选中的全部执行
  4. 执行：换类型时，用新类型中与该叶子当前函数最接近的函数初始化（叶内 4³ 个采样点上的最小二乘，值 ≥ 0），
           使模型保持在已求解状态附近；切分保持函数不变；下一轮求解从这里继续
直到：没有净收益为正的选项 / 剩余预算不到 1% / 达到最大轮数 → 最后一轮全分辨率严格求解
导出：存储值和阶跃几何四舍五入到半精度（不再重新拟合；若有值超出半精度范围直接报错），评测，写入紧凑文件
```

## 目录
```
adaptive_ct/
  core/            config.py  geometry.py  projector.py(CUDA 投影器封装)
  data/            dataset.py  splits.py
  representation/  octree.py(三种叶子、切分、类型转换)  factory.py
  evaluation/      metrics.py  render.py  volume.py
  codec/           budget.py(字节计数)  quantize.py(半精度舍入)  artifact.py(紧凑文件)
  refinement/      decision.py(局部重新拟合与选择)  controller.py(每轮决策、停止条件)
  training/        loop.py  solve.py  export.py  validate.py  __main__.py
  viewer/          server.py + web/
native/            bernstein_octree.cu(八叉树精确积分、反投影、决策统计)  projector.cu(稠密体投影，仅查看器用)  ext.cpp
configs/stage7/    p1.yaml（主线）  p0.yaml（只用常数叶的对照）  p1_24mib.yaml（3 倍预算诊断）
scripts/audit/     gate_chain.py：离线诊断（用到 GT，只用于分析，不进入流水线）
tests/             与 adaptive_ct/ 镜像
```
依赖只自上而下：core ← data ← representation ← evaluation ← codec ← refinement ← training；viewer 只读复用下层。

## 视角划分
- 训练 240 个视角：求解和决策只用这些。
- 检验 16 个视角：每轮报告投影误差，不参与任何决策。
- 测试 4 个视角：只在最后评测。

## 运行
```powershell
.venv\Scripts\python.exe -m adaptive_ct.training --config configs\stage7\p1.yaml
scripts\test.ps1
```
环境：项目内 `.venv`（Python 3.10，torch 2.11.0+cu130，匹配本机 CUDA 13.0，可重编原生扩展）。
每轮报告：求解遍数、是否收敛、合并像素倍数、检验视角投影 PSNR、字节、叶子类型数、GPU 显存峰值；
每次决策：字节价格 λ、各选项收益为正的叶子数、执行的动作数、这批动作的检验收益、决策用时。

## 已知缺口
- 决策原先只用 16 个视角，统计噪声大（见上表）；已改为 240 个视角，效果待测。
- 字节有价格以后，三线性叶换成阶跃叶（省 4 字节）仍被大量采用，平坦区域出现块状。
- 扫描圆外仍占 24% 的字节（那里只被部分视角照到，按常规应视为零或保持粗网格）。
- 投影域的检验收益看不到投影零空间中的体积误差；保边正则（在检验视角上选强度，候选包含 0）尚未实现。
- 阶跃几何只在决策时由当前重建估计一次，求解时不优化方向 / 位置 / 宽度。
- 切分收益按"父函数 + 每个子叶一个常数修正"估计，对三线性父叶偏保守。

只保留当前方法：旧的训练方式、旧的压缩编码、采样积分、高阶多项式叶、随机射线打分等都已从代码中删除，
历史版本只在 git 记录里（标签 `legacy-adam-pipeline` 和此前的提交）。
